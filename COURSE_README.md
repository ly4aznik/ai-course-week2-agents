# Агентный ИИ: теория и инженерия

Материалы курса для магистрантов MMCS, осень 2026. Здесь лежат слайды и практики по неделям: материалы недели появляются к её началу.

Агент — это модель в цикле: она выбирает вызов инструмента, наш код его выполняет и возвращает результат. Курс разбирает каждый слой такой системы и учит собирать из них работающие агенты.

## С чего начать

Соберите рабочее окружение по [инструкции недели 1](week1/setup.md) — без него практики делать нечем. Дальше идите по неделям.

## Что понадобится

Своя машина с Python и VS Code, агент для кода (Claude Code, Codex или другой) и ключ к модели через OpenAI-совместимый API. Подписки на сервисы студент оплачивает сам; подойдёт любой сервис, работающий из России без VPN. Ключ нужен с первого занятия: имитации модели в практике нет, и без ключа ноутбук останавливается.

## Выполненное задание недели 2

Из корня репозитория после установки [uv](https://docs.astral.sh/uv/getting-started/installation/) выполните одну команду:

```powershell
uv run python check.py --n 3
```

uv создаст окружение и установит версии из `uv.lock`. По умолчанию используются OpenRouter и `openai/gpt-6-luna`; ключ вводится через скрытый запрос getpass, в файлы он не записывается. Для повторяемой конфигурации скопируйте `.env.example` в `.env` и задайте OPENROUTER_API_KEY, OPENAI_BASE_URL, MODEL. Вместо OpenRouter можно указать другой OpenAI-совместимый сервис; если каталога цены для него нет, задайте PRICE_INPUT_PER_TOKEN и PRICE_OUTPUT_PER_TOKEN (USD за один токен). Ключ и `.env` не входят в Git. На чистой машине нужны Git, uv и сетевой доступ к провайдеру; uv может установить подходящий Python.

Команда выполняет 10 задач по три раза для каждого из двух описаний (60 траекторий), сохраняет отдельные журналы JSONL в новом каталоге `runs/`, `records.json`, `summary.json` и отчёт `week2/REPORT.md`. Если естественных неудач меньше трёх, дополнительно выполняются помеченные диагностические сценарии с искусственными сбоями; в A/B-метрики они не включаются. `--no-diagnostics` отключает их, `--max-steps` задаёт предел обращений к модели (по умолчанию 6).

Пять инструментов и схемы — `assignment/tools.py`; цикл без фреймворка — `assignment/loop.py`; задачи и критерии — `assignment/cases.py`; статистика — `assignment/metrics.py`. База `week2/practice/poi.sqlite` уже в репозитории, запросы только читают её, результаты списков ограничены десятью строками. OSM/ODbL и исходный снимок сохранены.

Локальные инженерные тесты без API: `uv run python -m unittest test_assignment -v`. Подставные ответы используются только в этих тестах, а эксперимент вызывает настоящую модель. [Отчёт задания](week2/REPORT.md). [Выполненный ноутбук](week2/practice/week02_agents.ipynb) и [его отдельный отчёт](week2/practice/LIVE_VALIDATION.md).


Итог сохранённого эксперимента: 60/60 основных попыток успешны, pass@1=pass^3=100% в обоих вариантах, выбор инструмента и аргументов 30/30. Отдельно сохранены три диагностических сбоя; они исключены из основных метрик. Полные описания не улучшили качество на этой выборке, но были дешевле в наблюдавшихся условиях кэша. [Двухстраничный PDF-отчёт](output/pdf/assignment_report.pdf).

Первичный оценщик отвергал эквивалентные записи часов и форматированный телефон; ошибка исправлена и покрыта тестами. Для воспроизведения пересчёта сохранённых ответов без API: `uv run python rescore.py runs/20261012T182559Z`. Первые оценки доступны в records.v1.json/summary.v1.json и JSONL, новые добавлены как reevaluation. `--diagnostics` разрешает дополнительные реальные запросы для диагностических сценариев. Содержание первичных модельных траекторий сохранено.

Повторно собрать PDF именно этого сохранённого эксперимента: `uv run --group report python make_report_pdf.py`. Нужен Arial (Windows) или DejaVu Sans (Linux); для других систем задайте REPORT_FONT и REPORT_FONT_BOLD. PDF содержит ровно две страницы; Markdown-отчёт и сырые журналы имеют дополнительные ссылки для аудита.
